# YtreeNova contextual F1 help source (English)

Edit this file to improve runtime help popup text. It is the authored source for contextual `F1` help.

Warning: the current authored `F1` prose is structurally usable but not yet at the intended quality bar. It needs further writing and editing work.

English is the canonical source of meaning and structure for contextual help. Localized variants may improve local wording directly, but any new substantive help content should be added here first so locale files do not diverge in meaning, topic inventory, or link structure.

## Topic-block schema

Every topic block in this file follows the same parser-facing contract:

1. The block starts with a level-2 heading in the exact form `## topic:<topic-id>`.
2. The heading is followed immediately by a fenced metadata block labelled `ytnova-help-meta`.
3. The metadata block contains exactly these keys, in this order:
   * `title:` — plain-text topic title.
   * `contexts:` — comma-separated stable runtime context/prompt IDs, or the literal `none` for link-only explainer pages.
4. The block then contains these sections in order:
   * required `### Contextual F1`
   * optional `### Explainer links`
   * required `### Long form`
5. When `### Explainer links` is present, every item uses Markdown link syntax with a `topic:` target, for example `- [Navigation](topic:navigation)`.
6. `### Long form` contains one or more level-4 subsections (`#### ...`). Their order is preserved as-authored for later projection.

Keep links shallow. Start with the current context. Jump to one shared explainer only when the short page is not enough.

Authoring rules:

1. Write for the user who pressed `F1` because they need help right now. Use plain language and say what they can do here.
2. Lead with actions. Name the key, say what it does, and say what happens next.
3. When one short line is enough, keep it to one short line. Keep local pages scannable.
4. Explain the parts that are not obvious from the key name alone, especially unusual keys, prompt flows, options, and ytnova-specific syntax or wildcard behavior.
5. Put repeated behavior on one owning page. Local pages should link to that page and explain only the local difference or local use.
6. Keep command rows short, but not cryptic. For prompt-driven or option-heavy commands, say what the user types, what ytnova does with it, and any tagged-file variant before you send them elsewhere.
7. Do not add a link when the visible page can explain the command in one clear line. One-line help belongs where the command is visible.
8. Page titles may end in `Help`. Contents entries and explainer links should not.

## topic:navigation
```ytnova-help-meta
title: Navigation
contexts: none
```
### Contextual F1
Use this page when you just want to move around a ytnova list.
`Up/Down` move one row at a time. `Right` usually opens or expands the selected row, and `Left` usually goes back or collapses it.
`Enter` opens the selected row. `PgUp/PgDn` move a screen at a time. `Home/End` jump to the top or bottom.
`/` starts a jump by name: press `/`, type letters, then press `Enter` to land on the best visible match.
If one screen changes any of those keys, that screen explains the exception on its own help page.

### Explainer links
- [Directory](topic:dir)
- [File](topic:file)
- [F7 Preview](topic:f7)
- [F8 Split](topic:f8)
- [F2 Picker](topic:f2-picker)

### Long form
#### Common list keys
* **Up/Down**: Move up or down one row.
* **Page Up/Page Down**: Move up or down one screen.
* **Home/End**: Jump straight to the first or last visible row.
* **Enter**: Open the selected item. In paired tree/file views, it may move you into the matching other view instead.
* **Left/Right**: `Right` usually opens or expands. `Left` usually goes back or collapses. If a page changes that, its own help says so.

#### Shared jump
* **/**: Press `/` to start a jump by name in the current list.
* **Type letters**: Type enough of the name to narrow the match down.
* **Enter**: Land on the best visible match.
* **Tree follow-up**: In tree views, repeat the jump inside the next directory if you want to go deeper.
* **Esc**: Cancel the jump and restore the original selection.

#### Help popup keys
* **Up/Down**: Move between selectable rows or links.
* **Page Up/Page Down**: Scroll longer help pages.
* **Home/End**: Jump to the top or bottom of the current help page.
* **Enter/Right**: Open the selected help item or linked topic.
* **Left**: Go back one step.
* **Esc/Quit**: Close the popup.

#### Local exceptions
* **Archives**: `\` jumps to archive root, or leaves the archive when you are already there.
* **Split**: `Tab` switches the active panel.
* **Preview**: `Shift-Up/Down`, `Shift-PgUp/PgDn`, `Shift-Home/End`, `Ctrl-P`, and `Ctrl-N` scroll the preview.

#### Jump model

* **Scope changes**: Filtering, Showall, Global, archives, and split mode all change which visible list `/` searches.

## topic:tagged
```ytnova-help-meta
title: Tagged
contexts: none
```
### Contextual F1
Tags let you build a working set, then run one command against that set.
When tags exist, copy, move, view, archive, and search often act on the tagged set instead of only the current row.
`Filter` owns the tagged-only scope toggle; press `F`, then `Tab` to turn the current tagged set into its own temporary list without changing the tags.

### Explainer links
- [File mode](topic:file)
- [Showall](topic:showall)
- [Filter help](topic:filter)

### Long form
#### Tagged basics
Tags are a working set. They are not a second clipboard and not a saved search.
Build a set, act on it, narrow it, then clear or invert it.

#### Common tagged flows
* **Tag** and **Untag**: Add or remove the current row from the working set.
* **Invert Tags**: Flip tag state inside the current visible scope.
* **Filter**: Press `F`, then `Tab` to switch the current file-list scope between all rows and tagged-only rows without changing tag state.
* **Copy tagged** and **Move tagged**: Send the whole tagged set to one destination.
* **View tagged**: Open the tagged files one after another.
* **Search tagged**: Search only the tagged files, then untag non-matches.
* **Archive**: Archive the tagged set first. When nothing is tagged, archive falls back to the current selection.

## topic:copy-move-targets
```ytnova-help-meta
title: Copy/Move Targets
contexts: none
```
### Contextual F1
Copy, move, and pathcopy use two explicit prompts.
First choose the replacement name or wildcard rename pattern.
Then choose the destination directory.
Merging them would hide meaning instead of removing friction.
After that, only real safety prompts may follow.
Overwrite conflicts compare size/time so you can judge newer/older and bigger/smaller.
For directories, no copy-now or move-now confirmation follows.

### Explainer links
- [Directory](topic:dir)
- [File](topic:file)
- [Archive File](topic:archive-file)
- [F8 Split](topic:f8)

### Long form
#### Target forms
* **Directory path**: Keep the original names under another directory.
* **Replacement name**: Rename one selected item on the way out.
* **Wildcard pattern**: Rewrite each selected basename by pattern, such as `copy-*` or `*.bak`.

#### Prompt flow
* **First prompt**: Choose the replacement name or wildcard pattern.
* **Second prompt**: Choose the destination directory.
* **Tagged copy/move**: Uses the same target syntax as single-item copy/move.
* **Pathcopy**: Preserves the selected file's path relative to the current volume root.
* **Split default**: Starts with the other panel's directory, but you can replace it.
* **Archive-backed copy/move**: Uses the same destination model even when extraction is involved.

#### Safety checks
* **Prompt count**: Only real safety prompts may follow.
* **Missing directory**: If the destination directory does not exist, ytnova asks whether to create it.
* **Conflict details**: Overwrite prompts show source and destination size/time facts when available.
* **Directory flow**: After you accept the destination, ytnova starts the directory copy or move. No extra copy-now or move-now confirmation follows.

## topic:vi-keys
```ytnova-help-meta
title: Vi Keys
contexts: none
```
### Contextual F1
With `VI_KEYS=1`, lowercase vi movement keys stay active.
Commands that would collide move to uppercase or another safe key.

### Explainer links
- [Navigation](topic:navigation)
- [Command-line editing](topic:command-line-editing)

### Long form
#### Navigation remap
With `VI_KEYS=1`, lowercase `h`, `j`, `k`, and `l` become `Left`, `Down`, `Up`, and `Right`.
`Ctrl-U` and `Ctrl-D` become page up and page down.

#### Command collisions
Commands that would steal those lowercase keys move out of the way.
Examples include `J compare`, `K volume`, `D delete tagged`, and `U untag all` where those actions exist.

## topic:theming
```ytnova-help-meta
title: Theming
contexts: none
```
### Contextual F1
Themes style semantic roles, not one-off screen positions.
That keeps help, picker, selection, footer, and warning surfaces readable as one system.

### Explainer links
- [F10 config](topic:f10)

### Long form
#### Theme model
Themes set semantic roles such as `footer`, `help`, `help_keybind`, `help_link`, `help_link_selection`, `selection`, `picker`, and `warning`.
`footer` owns footer-style command strips, while `help` owns the F1 reading body and `help_box_lines` owns the popup frame.
Linked explainers use `help_link`, and the active linked target uses `help_link_selection`, so help pages stay readable without hard-coded colors.

#### Editing path
Use `F10` to open the theme or config editing path.
Keep high-frequency navigation surfaces readable first: selection, picker, footer, and help.

* **Filter**: Filter this file list. `Tab` switches between all files and tagged files when tags exist.
* **Global**: Open the cross-volume file list.
* **Invert**: Flip tags in the visible scope.

* **Makedir**: Create a directory.
* **Newfile**: Create an empty file here.

* **Quit**: Quit ytnova.
* **Rename**: Rename the selected directory.
* **Showall**: Open the current-volume file list.
* **Tag**: Tag the files under the selected directory.
* **Untag**: Remove those tags.
* **moVedir**: Move the selected directory branch.
* **eXecute**: Type a shell command. Use `{}` where the selected directory path should go, and leave `{}` unquoted so ytnova can quote the path safely.
* **Z archive**: Archive the tagged set first, or the current selection when nothing is tagged.
* **/ jump**: Press `/`, type letters, and press `Enter` to land on the best visible match in this tree.
* **\` dotfiles**: Show or hide hidden names.
* **F10**: Open configuration.

### Long form
#### Live commands
* **F8**: Return to single-panel mode.
* **Tab**: Change the active panel.
* **Target defaults**: Copy, move, and compare default to the inactive panel.
#### View and scope

* **`2`**: Attributes. In file lists this also shows `name -> target` for symlinks.

* **`7`**: Show a small text preview on each visible file row. It leaves Compact so you can see the text.
* **`8`**: Show file detail text on each visible file row. It leaves Compact so you can see the summary.

* **Extra state label**: `5`, `7`, `8`, and `9` do not stack in the stats label. It shows only the one extra state you can currently see.

* **Hex**: Open the selected file in hex view.
* **Invert**: Flip tags in the visible scope.
* **J compare**: Compare the selected file with another file.
* **K volume**: Open the volume menu.
* **Log**: Log a directory or archive without leaving split file mode.
* **M/^N move**: `M` moves the selected file. `Ctrl-N` moves the tagged set. In split mode the other panel is the default destination.
* **Newfile**: Create an empty file.
* **Output**: Export the selection. `Ctrl-O` reuses the prompts for the tagged set.
* **Pipe**: Type a shell command and feed it the contents of the selected file on standard input.
* **Quit**: Quit ytnova.
* **Rename**: Rename the selected file.
* **Sort**: Change the file-list sort order.
* **Tag**: Tag the selected file. `Ctrl-T` tags every visible file.
* **Untag**: Remove the selected tag. `Ctrl-U` clears tags in this scope.
* **View**: View the selected file. `Ctrl-V` views the tagged files one after another.
* **eXecute**: Type a shell command. Use `{}` where the selected file path should go, leave `{}` unquoted so ytnova can quote it safely, and use `Ctrl-X` to repeat the command once per tagged file.

## topic:applications-menu

```ytnova-help-meta
title: Applications Help

```
### Contextual F1
Use Enter to select the highlighted preset.
After launch, ytnova keeps running and the application continues on its own.
Use E to edit the applications catalog that backs application presets.

Use {} for the file or folder currently selected in ytnova.

### Explainer links
- [Navigation](topic:navigation)

### Long form
#### Applications actions
* **Select preset**: `Up` and `Down` move through the preset list.
* **Launch behavior**: `F9` starts the selected preset and returns straight to the TUI. Use it for repeat-heavy external workflows, not for one-off shell typing.
* **Use `eXecute` for one-offs**: The `X` command prompt stays the ad hoc shell surface with history and terminal-style output. Use it when you need a one-off command.
* **Edit presets**: `E` opens the dedicated applications catalog so presets can be changed without leaving the chooser family.
* **Selection and working directory**: `{}` inserts the current file or folder. Presets also start in that directory, so scripts without `{}` still run from the place you selected.
* **Prompt text**: `{input}` inserts the extra text you typed for the preset prompt.
* **Starter presets**: The bundled catalog starts with `xdg-open` launchers and includes commented examples for tools such as `mpv` or local helper scripts.
* **Cancel menu**: `Esc` closes the chooser without selecting a preset.
