Summary
- Reproduced the CI failure locally: after `make clean && make`, `./build/ytnova --version` exited with `EXIT: startup invariants not configured`.
- Root cause was not in the generated AppState registry data itself; it was the manual startup-required tables in `src/core/main.c` falling behind the newly added explicit records.
- The explicit watcher-refresh and modal-completion change added:
  - two transition ids
  - one dispatch surface id
  - two transition-sequence scenario ids
  but `kAppStateRequiredTransitionIds`, `kAppStateRequiredDispatchSurfaceIds`, and `kAppStateRequiredTransitionSequenceScenarioIds` were not updated.

Diagnosis details
- Existing contract tests already covered this invariant, so I used them as the red proof.
- Focused red run:
  - `source .venv/bin/activate && pytest -q tests/test_appstate_contract_guard.py -k 'runtime_transition_registry_startup_requires_documented_transition_ids or runtime_dispatch_surface_startup_requires_documented_surface_ids or runtime_transition_sequence_startup_requires_documented_scenario_ids'`
  - Result: 3 failures showing `main.c` required tables no longer matched the docs/runtime registries.
- Semantic inspection confirmed the mismatch at the top of `src/core/main.c`:
  - transition table lacked `transition.modal-action.completion` and `transition.refresh-rebuild.watcher-live-refresh`
  - dispatch-surface table lacked `surface.modal-completion-event`
  - transition-sequence table lacked `sequence.modal-completion` and `sequence.watcher-live-refresh`

Implementation
- Updated only `src/core/main.c`.
- Aligned the required startup tables with the documented runtime order/contents.
- Kept the fix scoped to the active PR branch and amended the existing commit.
