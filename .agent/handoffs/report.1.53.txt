Summary
- Added a required runtime event-id table in src/core/main.c matching docs/appstate_event_coverage.json event IDs.
- Updated AppStateEventCoverageReady() to require both documented event classes and documented event IDs before startup can proceed.
- Added a focused contract-guard test that parses the required event-id table from main.c, compares it to the event coverage docs, and verifies the startup invariant uses the table.

Changed files
- src/core/main.c
- tests/test_appstate_contract_guard.py
- Existing unit scaffold changes remain in include/ytnova_appstate_actions.h, src/core/appstate_actions.c, and scripts/check_appstate_contract.py.

Audit finding fix
- The prior validator only proved class coverage. A runtime row could rename event.render-reflow (or any documented ID) while preserving class, transition, category, and write-set, leaving startup validation green.
- AppStateEventCoverageReady() now compares AppStateEventCoverageCount() against both kAppStateRequiredEventClasses and kAppStateRequiredEventIds, then calls AppStateRequiredEventIdCovered(kAppStateRequiredEventIds[index]) for every documented ID. Because AppStateRequiredEventIdCovered uses AppStateEventCoverageLookup(), a missing or renamed documented runtime event ID fails closed at startup.
- The new test test_runtime_event_coverage_startup_requires_documented_event_ids failed before the fix because kAppStateRequiredEventIds did not exist, then passed after the runtime table and startup lookup check were added.
