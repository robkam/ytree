Runtime boundary approach
- Added AppStateValidatedKeyAction(action) in src/core/appstate_actions.c and declared it in include/ytnova_appstate_actions.h.
- The helper returns ACTION_NONE unchanged as the intentional no-op/fail-closed result.
- For every non-ACTION_NONE action, the helper requires AppStateActionCoverageLookup(action) to return matching coverage and AppStateTransitionLookup(coverage->transition_id) to return transition metadata; otherwise it fails closed to ACTION_NONE.
- Routed GetKeyAction decoded returns in src/ui/key_engine.c through AppStateValidatedKeyAction without changing keybindings, action enum values, or controller dispatch.
- Added guard tests that verify valid covered actions pass, invalid/missing coverage fails closed, a copied local metadata record with a missing transition fails closed without mutating production metadata, and GetKeyAction routes decoded ACTION_* returns through the AppState boundary.

Residual risks / follow-up suggestions
- The runtime boundary is intentionally narrow: controller dispatch is unchanged and still receives legacy actions when they have AppState coverage plus transition metadata.
- GetKeyAction now performs one registry lookup pair per decoded key action; this is cheap for the current static tables, but future large registries may want indexed transition lookup if profiling ever shows input latency impact.
