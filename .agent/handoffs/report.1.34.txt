Audit report: AppState invariant runtime lookup scaffold

Decision: FAIL

Findings

1. Severity: high
   File: scripts/check_appstate_contract.py:518-539, scripts/check_appstate_contract.py:559-561, scripts/check_appstate_contract.py:859-864
   Evidence: The runtime invariant parser only records rows that match the strict string-literal row regex. It does not verify that every initializer inside `kAppStateInvariants[]` was consumed. A targeted mutation that appended an extra compiled-style runtime row with `NULL` as `invariant_id` produced `PASS: AppState contract guard passed` from `python3 scripts/check_appstate_contract.py --action-runtime <mutated runtime file>`. Because the malformed extra row is ignored, `covered_ids` still equals the documented ids and the missing-id check does not fire.
   Impact: The acceptance criterion requiring the Python contract guard to detect extra runtime invariant rows is not met for malformed/null extra rows. A bad runtime registry row can pass `make qa-code-quality` even though startup validation would fail closed and abort normal app startup once that row is compiled in.
   Concrete fix: Make `_parse_runtime_invariant_registry` fail closed on unparsed registry entries. For example, split or scan the `kAppStateInvariants[]` body into top-level initializer rows, require each row to match the expected schema, and report any unparsed row by index before validation. Add a regression test that appends an extra runtime invariant row with a non-string/null id (or otherwise malformed schema) and asserts the guard fails.
