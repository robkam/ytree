Findings

1. Severity: high
   File: scripts/check_appstate_contract.py:553-570, scripts/check_appstate_contract.py:624-632, src/core/appstate_actions.c:109-120
   Evidence: `_parse_runtime_invariant_registry` parses the invariant field arrays with `re.findall(r'"([^"]+)"', ...)` and then trusts the extracted string literals as the full runtime field list. It does not split those array initializers into top-level entries or fail on unparsed entries. A targeted mutation that inserted `NULL,` into `kAppStateInvariantProtectedFields0[]` still produced `PASS: AppState contract guard passed` from `python3 scripts/check_appstate_contract.py --action-runtime <mutated runtime file>`.
   Impact: `make qa-code-quality` can pass while the compiled runtime metadata contains a malformed invariant field array. Startup validation would fail closed because `sizeof(kAppStateInvariantProtectedFields0) / sizeof(kAppStateInvariantProtectedFields0[0])` includes the `NULL` element and `NonEmptyStringList` rejects it, so the guard no longer proves that runtime invariant metadata mirrors `docs/appstate_invariants.json` exactly for the declared list fields. This leaves the same class of unparsed-runtime-metadata gap that the top-level malformed-row correction closed, but inside the protected-fields/transition-ids/dispatch-surface-ids/migration-notes arrays.
   Concrete fix: Reuse the fail-closed top-level initializer scanning approach for each `kAppStateInvariant{ProtectedFields,TransitionIds,DispatchSurfaceIds,MigrationNotes}N[]` array. Require every array entry to parse as a string literal, report malformed/unparsed entries by array name and index, and add a regression that injects a non-string entry such as `NULL` into an invariant metadata array and expects the contract guard to fail.
