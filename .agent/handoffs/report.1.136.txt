Summary
- Audited the current working-tree changes for AppState action/event transition_sequence_refs.
- The docs/runtime metadata additions are present, the volume menu transition sequence is present, and focused/full AppState contract guard tests plus the clean build run green locally.
- Gate decision: FAIL because wrong-transition sequence refs are not fail-closed when a record also contains any correct ref.

Findings
- Severity: high
  File: scripts/check_appstate_contract.py:3577-3612; src/core/main.c:999-1022; tests/test_appstate_contract_guard.py:6860-6928
  Evidence: `_validate_transition_sequence_refs` appends all matching steps into one record-level `matching_steps` list and only fails when no referenced sequence has a matching step. `AppStateTransitionSequenceRefsReady` similarly uses one record-level `transition_step_found` flag. Therefore an action/event/runtime record can declare `transition_sequence_refs` containing one valid sequence and one existing sequence for a different transition, and both the guard and startup readiness still pass. I confirmed with a direct helper probe: refs `['sequence.correct', 'sequence.wrong']`, where only `sequence.correct` covered the record transition, returned `[]` failures. The added tests cover a single wrong-transition ref, but not the mixed correct+wrong case.
  Impact: The acceptance criterion requiring wrong-transition sequence-ref fail-closed behavior is not satisfied. Runtime/docs drift also will not catch this if docs and runtime both carry the same stray wrong ref, so coverage records can overclaim transition-sequence coverage and startup readiness will still report ready.
  Concrete fix: Validate each referenced sequence independently: after lookup, require that sequence to contain at least one step whose `transition_id` equals the record transition id; emit a failure/return false for any ref that does not. Keep the aggregate matching steps for dispatch-surface field coverage if needed, but do not let one correct ref mask another wrong ref. Add focused tests with mixed correct+wrong refs for action coverage, event coverage, runtime action/event coverage, and startup readiness.
