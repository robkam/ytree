Context
- Current runtime metadata already has action-transition, transition, compatibility-shim, and invariant lookup scaffolds.
- This unit should follow those established patterns: read-only static metadata rows, lookup/count/index APIs, startup shape/linkage checks, and fail-closed Python guard parsing.
- docs/appstate_dispatch_surfaces.json fields are:
  - surface_id
  - category
  - source_path
  - entry_symbol_or_path
  - transition_id
  - boundary_status
  - allowed_direct_writes
  - migration_notes

Acceptance criteria checklist
- Add `AppStateDispatchSurfaceMetadata` and read-only API declarations/definitions:
  - lookup by surface id
  - count
  - indexed access
- Runtime rows mirror every record in docs/appstate_dispatch_surfaces.json for the fields above.
- List fields (`allowed_direct_writes`, `migration_notes`) are parsed/validated fail-closed by the Python guard; malformed/unparsed runtime list entries must fail.
- Unknown/null/empty dispatch surface id lookup fails closed with NULL.
- Startup invariant validation consumes the dispatch surface registry and verifies:
  - registry is non-empty
  - required scalar fields are non-empty
  - list fields are present as valid string arrays, allowing empty lists only where docs allow them
  - every runtime `transition_id` resolves through `AppStateTransitionLookup`
  - unknown lookup fails closed
- The Python contract guard validates runtime dispatch surface rows against docs and catches missing/extra/duplicate rows, field drift, malformed rows, malformed list entries, invalid transition linkage, and any existing invariant references to unknown runtime dispatch surface ids.
- Existing AppState guard behavior for action/transition/shim/invariant metadata remains green.
- No runtime UI behavior changes are introduced.
