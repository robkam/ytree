Findings

1. Severity: medium
   File: src/core/main.c:599
   Evidence: The new AppStateInvariantProtectsField helper passes metadata->protected_fields directly to StringListContains. StringListContains dereferences values[index] without checking values for NULL (src/core/main.c:269-278). This helper is called from AppStateOwnerFieldsReady before AppStateInvariantRegistryReady runs, so the existing invariant registry NonEmptyStringList protected_fields validation has not yet guarded the pointer.
   Impact: If runtime invariant metadata drifts to a NULL protected_fields pointer with a nonzero protected_field_count, startup can segfault before reaching the intended fail-closed readiness path. The new guard should reject invalid metadata by returning 0, not depend on later registry validation that is ordered after this call.
   Concrete fix: In AppStateInvariantProtectsField, fail closed before StringListContains unless the invariant protected field list is structurally valid, e.g. `if (!NonEmptyStringList(metadata->protected_fields, metadata->protected_field_count)) return 0;`. Add/adjust the startup shape test to require the protected_fields null/list validity guard.
