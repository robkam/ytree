Owner-field coverage approach
- Added explicit `owner_field_refs` to AppState action and event coverage docs immediately after `declared_write_set`.
- Set each action/event `owner_field_refs` list to the same canonical owner-field IDs as its declared write set, so coverage proves ownership-map alignment without replacing declared write-set semantics.
- Extended `scripts/check_appstate_contract.py` so action/event coverage rejects missing, malformed, duplicate, unknown, undeclared/mixed owner-field refs, and requires an explicit migration-note rationale if an empty write set ever has empty owner-field coverage.
- Extended runtime action/event metadata structs, tables, parsing, docs drift checks, and startup readiness validation to expose and fail-closed on owner-field refs that are unknown, duplicated, or not an exact cover of the runtime declared write set.
- No new `docs/appstate_owner_fields.json` entries were needed; all current declared writes already resolve to canonical owner-field registry records.
